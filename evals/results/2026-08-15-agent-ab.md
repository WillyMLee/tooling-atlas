# Measured Codex module A/B pilot — 2026-08-15

This report records the first real Tooling Atlas baseline/candidate agent pairs. It is not synthetic dashboard data.

## Test contract

- Each run used a fresh isolated Codex subagent with inherited model and reasoning settings. The exact runtime model identifier was not exposed.
- Baseline agents were instructed not to load an Atlas module.
- Candidate agents received the same task and fixture, plus one explicit instruction to load the named module.
- Every run was read-only. Correctness, evidence, instruction adherence, and safety were graded before efficiency.
- Elapsed time and tool-call counts were recorded by the agents. Tokens and cost remain `null` because this runtime did not expose them.
- This is replicate 1 of 2. The scorer therefore returns `collect-more`, even when a pair is directional.

## Batch Tool Calls

All six runs returned correct results with provenance and no writes. The common pair returned Alpine Works, Beacon Labs, Cedar Health, and Delta Freight in the requested order. The sparse-record pair explicitly returned `not provided` for Fjord Systems' owner and Grove Studio's renewal month. The failure pair retained Harbor Energy and Iris Media while naming `juno-malformed.json` and `kestrel-missing.json` once each.

The candidate did not improve any tested batch. Across the three pairs, baseline averaged 3.7 calls and 11.0 seconds; candidate averaged 5.7 calls and 29.1 seconds. The skill read and batching contract cost more than they saved for three-to-four file tasks.

Routing change: do not auto-trigger Batch Tool Calls for three or four reads. Use direct reads. Treat roughly eight independent operations as a provisional consideration threshold, require a strict return shape, and add a larger-batch regression case before reconsidering maturity.

## Context Budget

All six runs passed quality. The common pair produced the same six-module evidence map and the correct distinction between field observations and matched evidence. The edge pair found 11 sites, 11 design profiles, no missing or extra slugs, and complete required fields. The broad pair resolved all eleven sibling repositories and surfaced real specification drift in MotionDeck, SoundDeck, Cost Basis, and Worth More.

The result is task-size dependent. Loading the module for the four-source task added three calls and 15.1 seconds. On the compact cross-source task it saved one call and 10.2 seconds. On the eleven-project audit it preserved quality while reducing elapsed time by about 38% and one tool call.

Routing change: stay direct for a handful of short sources. Use Context Budget when source count, output volume, repeated retrieval, or handoff risk makes a compact working set and resume packet valuable. Replicate both the small and broad cases before claiming a general improvement.

## Scorer decision

- Batch Tool Calls: `3 / 6` required pairs, quality passed, primary improvement `-58.3%`, decision `collect-more`.
- Context Budget: `3 / 6` required pairs, quality passed, primary improvement `-43.4%`, decision `collect-more`.

The percentage above is the scorer's mean per-pair change in tool calls. It intentionally does not substitute elapsed time or one favorable broad case for the declared primary metric.
